## 二、必须知道的坑

### 1. 政府站点没有 RSS

国务院、发改委、工信部**都不提供 RSS**。列表页多为 JS 动态渲染，
静态请求拿不到内容。

**结论**：政策源必须用浏览器渲染（playwright），或干脆放弃。

### 2. 政府采购网有 IP 级频率限制

```
症状：返回「频繁访问!中国政府采购网」拦截页
表现：HTTP 200，但内容是拦截提示
```

**处理**：
- 必须走 **HTTPS**（HTTP 直接返回拦截页）
- 关键词之间**强制等待 60 秒**
- 即便如此，长期高频仍可能被限

**影响**：招标情报**无法实时**。这是结构性限制，不是代码问题。

### 3. 中标公告有三种表格版式

同一个网站上，中标详情页的表格结构**不止一种**：

| 版式 | 表头 |
|---|---|
| A | `中标供应商名称` |
| B | `供应商名称`（多数） |
| C | 纵向「键：值」，**无标准表格** |

**只支持 A 时解析率 2/17；三种都支持后 17/17。**

版式 C 还有个陷阱：表头行本身是数据行，会把后续每个字段当成一个"供应商"，
需要形态学过滤（公司名长度、是否含冒号、是否有企业后缀）。

### 4. 政策关键词不能复用招标词表

政策标题**几乎不会出现**「AMR / AGV / 仓储机器人」这类招标品类词。

**实测**：复用招标词表时，**21 条政策全部被过滤**（相关度均为 0）。

**结论**：政策需要独立的词表（制造业 / 物流 / 新质生产力）。

### 5. 系统代理会导致随机失败

**症状**：部分站点连接失败，且**时好时坏** —— 同一站点半小时前失败、
之后又成功。

**诊断**：

```
requests.get(...)                     → ❌ 失败
requests.Session(); trust_env=False   → ✅ 成功
socket + TLS 握手                      → ✅ 成功
```

**结论**：系统代理（注册表 `ProxyEnable=1`）对部分国内站点分流失效。
13 个采集源实测：**走代理 3 个失败，直连 0 个失败**。

**处理**：采集器全部 `trust_env = False` 直连。需要代理的国外服务
（Tavily 等）在自己的调用处显式设置。

**这类问题最危险**：它不报错，只是悄悄丢数据。

### 6. 数据缺失时不要给结论

**实测发现的缺陷**：

原始实现在**完全空记录**上也会输出「行业动态，用于把握整体风向」；
在中标公告未解析出供应商时，仍断言「已有厂商拿下该单」。

**修复**：
- 无标题的记录**不产出判断**
- 证据不足时标注「未解析到供应商/金额，结论待确认」
- **媒体稿与政采稿分开措辞**（媒体的「订单信号」指行业动向，
  政采的「中标」指具体项目成交）

## 三、LLM 相关的坑

### 1. 静默失败会崩溃整个流程

部分服务在限流时返回：

```json
HTTP 200
{"error":{"message":"We were unable to start processing your request within the 900-second timeout limit."}}
```

**openai SDK 不抛异常**，正常解析出 `choices = None`，
于是 `response.choices[0]` 抛 `TypeError`，**整个分析中断**。

**处理**：调用返回后检查 `choices` 是否为空，为空则按可重试错误处理。

### 2. Key 预检验证可能是假阳性

**第三方项目的原始实现**用 `GET /openrouter.ai/api/v1/models` 校验密钥。
但该端点**是公开的**：

| 密钥 | 结果 |
|---|---|
| 真实密钥 | HTTP 200，462 个模型 |
| **伪造密钥** | **HTTP 200，462 个模型** |
| **空密钥** | **HTTP 200，462 个模型** |

**结论**：任何无效密钥都会被报成"有效"。

**处理**：改为 POST 一次最小化的 `/chat/completions`（`max_tokens=1`），
按状态码给出可操作提示（401 密钥无效 / 402 余额不足 / 404 模型名错）。

### 3. max_tokens 过小会截断长报告

实测 DeepSeek：

| max_tokens | finish_reason | 实际输出 |
|---|---|---|
| 2000 | **length（截断）** | 3438 字符 |
| 4000 | stop（自然结束） | 5848 字符 |
| 8000 | stop | 5257 字符（浪费） |

**结论**：长报告类调用用 **4000**。

### 4. 批量分析要留冷却时间

**实测**：连续跑 5 批后，第 6~8 批**全部返回空报告**（DeepSeek 突发限流）。

**处理**：
- 批次大小降到 3
- **批间冷却 20 秒**
- 空报告**自动重试**（冷却 40 秒后重跑该批）

**效果**：重跑 12 家 → **12/12 成功，零空报告**。

## 四、Windows 特有的坑

### 1. `.ps1` 必须带 UTF-8 BOM

否则 Windows PowerShell 按 ANSI 读取，中文变乱码：

```
「未找到」→「鏈壘鍒?」
```

### 2. `.bat` 必须用 CRLF 换行

用 LF 换行时，`@echo off` 不生效，**每一行 REM 注释都被当命令执行**。

### 3. `*>>` 写的是 UTF-16LE

```powershell
& $py script.py *>> $log        # ❌ UTF-16LE，编辑器打开是乱码
& $py script.py 2>&1 | Out-File -Encoding utf8 -Append   # ✅
```

读出来形如 `= = 1 .`（字符间带空格）。

### 4. 计划任务无法处理中文路径参数

把含中文的路径作为**命令行参数**传给 `cmd.exe` 时，ANSI 往返会破坏它：

```
'"D:\...\爬取\run.bat"' 不是内部或外部命令
```

**但手工双击运行是正常的** —— 这种"交互式能跑、计划任务不行"最难排查。

**处理**：用 PowerShell 启动器（Unicode 原生），并在脚本内 `cd` 到目录、
用**裸文件名**调用，避免中文路径出现在命令行参数里。

## 五、覆盖率现状

### 自研固定源的覆盖很窄

**实测**：45 个竞品中，**只有 12 个**能通过固定源采集到数据。

原因：

| 竞品类型 | 为什么抓不到 |
|---|---|
| 未上市（海柔创新、快仓、极智嘉…） | 无公告披露 |
| 做大型商业项目 | 不走政府采购 |
| 媒体曝光少 | 垂直媒体报道有限 |

### 互补方案

用 competitor-intel 的搜索引擎能力回补。实测运行后：

```
仅直采          : 12/45 (27%)
直采 + 分析来源 : 42/45 (93%)
```

**这就是两套系统做数据层打通的直接动因。**
